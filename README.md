## 部署到公网（可选）

本机跑不需要任何配置。如果部署到 Vercel 之类的地方，用两个环境变量控制：

| 变量 | 作用 |
|---|---|
| `WZZ_TOKEN` / `WZZ_UA` | 登录凭证。云端文件系统只读，所以凭证只放环境变量、不写盘 |
| `WZZ_ACCESS_KEY` | 访问密钥。**设了它之后，只有写操作需要登录** |

`WZZ_ACCESS_KEY` 的语义是「按需登录」，不是整站门禁：

- **不需要登录**：打开页面、看门店清单、看座位图、看订单、看月卡状态 —— 全部开放
- **需要登录**：订座、月卡抵扣、开门、签到、退座、取消预约、换座、延长、人脸建档

也就是说，不登录也能把整个流程逛一遍，只有真的要点「下单」那一刻，才会弹出项目自带的登录框（复用小程序样式的 `.dialog`，不是另做一页）。
本机跑时不设 `WZZ_ACCESS_KEY`，全部直通，行为完全不变。

密钥存在浏览器 `localStorage`，之后每个请求带 `X-Access-Key` 头；服务端只在校验写接口时比对它。

### 减少对平台的请求（防封号相关）

平台把「短时间大量访问同一账号」列为风控行为，所以读接口做了一层短缓存，**刷新页面不会每次都打到上游**：

| 接口 | 缓存时长 |
|---|---|
| `/api/status` | 20 秒 |
| `/api/orders` | 15 秒（带 `?force=1` / `?all=1` 时不缓存） |
| `/api/stores` | 5 分钟 |
| `/api/cards` | 1 分钟 |

同时并发的同 key 请求会**合并成一次**上游调用（响应头 `X-WZZ-Cache` 告诉你这次是 `hit` 还是 `miss`）。
**写操作永远不缓存** —— 下单、开门、退座这类请求每次都实打实发出去。

### 出口 IP 是否稳定

`GET /api/whoami` 返回这个实例当前看到的外网 IP。
Vercel 函数走 AWS Lambda，出口 IP 是固定的（实测 `iad1` 区域连续 20 次调用都是同一个地址），
所以从平台看，请求始终来自同一批机房 IP，不会像家宽那样「拨号就换地方」。
**但也正因为是机房 IP，这个部署只能给一个人用** —— 多人共用一个 token 才会触发异地/多设备风控。

## 这是什么

一个给自己用的本地小工具，替代微信小程序的部分操作：**在电脑上选座、下单、用月卡抵扣到 ¥0**，并直接控制自己订单对应的门锁 / 签到 / 退座。界面是一个尽量还原微信小程序外观的单页应用，跑在 `127.0.0.1:8790`。

> ⚠️ **仅供个人自用。** `auth.json` 里是你的登录凭证，等于你的账号本身 —— 别提交、别外传。若要部署到公网，务必设 `WZZ_ACCESS_KEY`（见下节），否则任何拿到地址的人都能用你的账号下单。

## 快速开始

```bash
cd booking-assistant

# node 不在默认 PATH 里，用绝对路径（v24 起自带 fetch / WebSocket）
NODE=/Users/Apple/.nvm/versions/node/v24.19.0/bin/node

$NODE book.mjs          # 前台跑
# 或后台跑： nohup $NODE book.mjs > /tmp/book.log 2>&1 &

open http://127.0.0.1:8790
```

**零依赖、零构建**：不需要 `npm install`，没有 `node_modules`，`book.mjs` + `ui.html` 就是全部。

停止：`pkill -f "node book.mjs"`

## 手机上看效果（同一 WiFi）

默认只监听 `127.0.0.1`，别的设备连不上 —— 这是故意的，因为 `auth.json` 是你的登录凭证。

```bash
$NODE book.mjs --lan          # 等价于 WZZ_HOST=0.0.0.0
$NODE book.mjs --lan WZZ_PORT=8899
```

启动横幅会把可用的局域网地址列出来，例如：

```
  → 本机   http://127.0.0.1:8790
  → 局域网 http://192.168.1.57:8790   (en0)
  ⚠ 已开放到局域网：同一网络下任何设备都能操作这个账号。看完请去掉 --lan。
```

> ⚠️ **开放到局域网 = 同网段任何设备都能拿你的账号订座/开门。** 咖啡馆、公司网、宿舍网都别长开。
> `bridge100` / `bridge101` 那几条是 Docker/虚拟机的虚拟网卡，手机连不上，忽略即可。

## 凭证怎么换（不用重启）

token 与 `User-Agent` **绑死**：UA 里微信版本号只差一位，服务端就返回 `12002 Token失效`。
所以换包时 **token 和 UA 要一起换** —— 用「我的 → 更新 JWT token」从抓包里一键提取最稳。

- 服务每 2 秒检查一次 `auth.json` 的 mtime，**改完立即生效，不用重启**。
- 也可以直接编辑 `auth.json`：`{ "token": "eyJ...", "ua": "Mozilla/5.0 ... MicroMessenger/8.0.xx..." }`
- 保存前会拿新 token 打一次探活接口，把结果告诉你。

## 功能

### ① 选座下单（核心）

`门店 → 选座 → 点座位 → 确认 → 下单 → 月卡抵扣`

- 只列 **月卡 0 元覆盖** 的门店（实时取自平台）。
- 下单后调抵扣接口：**扣月卡 1 天，实付 ¥0，订单直接变「已支付」**。
- **取消预约不退月卡天数** —— 实测「抵扣 → 取消」前后卡内余额不变。取消只释放座位。

### ② 当前状况（选座页实时卡）

选座页顶部一张「当前状况」卡：服务端时间、营业状态、此刻座位（空 N · 占 N）、我正占着的座、我的订单、灯光、门锁状态。

### ③ 看占座的人 + 该座被预约的时段

座位图上**点占用的座位**：弹出半屏抽屉，显示那个人的头像（方形，精确落在座位点上）、`userId` 尾号，
以及这个座**被占用的所有时间段**（已标出「占用中 / 已被预约 / 已过去」）。
选座页还有一张全场已预约时段的总览，按人数排序。

> 平台**不暴露**别人的昵称或别人的订单：只有头像 + `userId`。

### ④ 订单操作（订单详情页）

| 动作 | 状态 |
|---|---|
| 开门 | ✅ 实测通 |
| 签到（到店入座） | ✅ 实测通（订单 → 使用中） |
| 退座（结束本次学习） | ✅ 实测通（订单 → 已结束，座位立即释放） |
| 取消预约 | ✅ 实测通（订单 → 已取消，座位立即释放）<br>⚠️ **只对「已支付」的单有效**，待支付的单平台会直接拒绝 |

**关于「提前 30 分钟取消」**：门店规则由平台的取消规则接口给出，
开始前 30 分钟以上取消不扣减；30 分钟以内算违约，扣 30 分钟。
订单详情页会按开始时间**实时判定**并显示绿/橙提示。
⚠️ 但要清楚：**取消不退月卡天数**。

**关于「签到自动亮灯」**：签到会自动点亮灯光、并把预约窗口重定基（改成「签到那一刻 + 原时长」）；退座会把灯关掉。
所以想要灯亮，点签到就够了。

### 开门的时间窗（重要）

平台允许提前开门的时间由门店字段 `advanceOpeningTime` 给出，**实测是 45 分钟**：
订单开始前 45 分钟起才能下发开门指令，早于点这个时间平台不会受理。

代码里按这个字段**自己先判一遍**，不靠平台拒绝：

- 订单详情页的「开门」按钮，没到窗口就是**禁用**的，旁边写明「从 HH:MM 起可以下发开门指令 · 还差 N 分钟」
- 订单列表卡片的「可开门」标记用**同一套判定**，只会显示 `09:15 可开门` 这种具体时间点，不会出现「列表说能开、点进去按钮是灰的」
- 状态为「使用中」的单视为已在店内，不再受这个窗口限制

> 这个判定以前是坏的：`/api/order` 返回的是 `date` + `begin` 两个字段，
> 而旧代码去读 `beginTime` / `studyBeginTime`，拿到 `undefined` 算出 `NaN`，
> 导致**任何时候都判定为可开门**。现在统一由 `orderBeginAt()` 拼装时间，并对 4 种字段形态做了单测。

> 每个写操作（开门 / 签到 / 退座 / 取消）都强制二次确认，服务端也会再拦一道 `confirm:true`，防止误触。

### 登录框出现在哪一步

需要登录的操作，**登录框一定出现在确认框之前**，也就是你点下去看到的第一个框就是「登录后继续」。
没登录时前端**一个写请求都不会发出**（不是先发出去再拦）。
实现上每个写操作的点击处理器第一行就是 `jpostAuth.ensure(reason)`，通过之后才弹确认框。

### ⑤ 人脸门禁（我的页）

上传一张正脸照片 → 传到平台 → 建立人脸档。建完之后**到门禁机刷脸就行，不用每次在网页点开门**。

> ⚠️ **这是真的会建/覆盖人脸档，而平台没有删除接口。** 所以该操作必须带二次确认。
> 平台**没有**「查是否已建过脸」的接口，所以界面显示不了状态；**重复上传会覆盖旧的脸**。

### ⑥ 订单

「预约」页**直接列出当前预约**，不用先查单。

平台的订单接口只返回**活跃**订单 —— 退座 / 结束后就从列表消失，所以工具在**本机 `localStorage`** 留了一份足迹（「本机记录」），
已结束的单点一下就能回查。

## 订单状态

以前卡片页脚直接印 `orderStatus = 4`，看不懂。现在统一走 `statusText()` 转译：

| 码 | 显示 | 来源 |
|---|---|---|
| 1 | 待支付 | 实证 |
| 3 | 已支付（待使用） | 抵扣后回读 |
| 4 | 已取消 | 真单实测（取消后 3→4） |
| 5 | 已关闭 | 实测出现，**文案是推测** |
| 6 | 使用中 | 时段内回读 |
| 7 | 已退款 | 实测出现，**文案是推测** |
| 8 | 已结束 | 退座后回读 |

> `STATUS_ZH` / `STATUS_TONE` 是本地兜底表，优先用服务端返回的状态文案。5 和 7 平台不返回文案，
> 是照前端习惯推的 —— 如果你在原 App 里看到别的叫法，改 `ui.html` 里那张表即可。

## 换座 / 延长时间

### 换座

`POST /seat/order/changeSeat`，form-urlencoded：`orderId` + `seatId`（要换到的新座位）+ 可选 `spaceId` / `storeId`。

> ⚠️ 这个接口**用已结束/已取消的单调用也会返回「操作成功」，但什么都不改**。
> 所以本地实现**不信响应码，只认回读**：拿订单详情回读 `seatId`，变了才算成功。
> 参数名是按平台命名习惯推的，**没能在活跃订单上实测**。

### 延长时间

平台**没有独立的延长接口**。延长走的就是抵扣接口 —— 它的请求体里本来就有 `extendOrderId` 字段。

> ⚠️ 参数未实测。本地实现会带上 `extendOrderId` 发一次，并把服务端**原样返回**给你看，成功与否以**回读结束时间有没有变**为准。

## 座位坐标系

官方小程序的座位定位是 `left/top` = **左上角**，而早先这版按「中心点」画（`transform:translate(-50%,-50%)`），
整体会偏半个座位宽 —— 这就是「头像没落在座位点上」的成因。

`.map.anchor-tl` / `.map.anchor-c` 两个 class 对应两种坐标系，选座页有开关，默认 **左上角**，记在 `localStorage`。

## 已知问题与边界

### 平台侧数据问题：地址重复

平台的地址字段本身就可能重复（`storeAreaName` 出现「重庆市重庆市渝北区」这种）。

`dedupeAddr()` 统一处理：去掉 `市辖区` 占位符，再把连写两遍的市/区/县折叠成一遍。
`normalizeStore()` 的字段优先级是 `storeAreaAll` → `storeAreaTotal` → `storeAreaName`。

### 已知做不到的

- **退卡 / 退款**：平台没有接口。取消不退月卡天数。
- **微信支付**：要客户端 + 商户号；0 元店用不上。
- **查别人昵称 / 别人的订单**：只有头像 + `userId`。
- **补差价升级 / 自助转让**：升级接口返回「该方法已废弃」；转让只有店长人工流程。
- **开灯**：接口存在，实测有活跃订单时返回 `code 500`（空 msg）、无活跃订单时返回「当前订单未在进行中」。
  灯实际由**签到点亮、退座关闭**，所以想亮点签到、想关点退座，状态看 `lightOpenStatus`。

### 踩过的坑

- 订单详情接口是 **GET + query 参数**，用 POST body 会 500。
- 平台未知路由返回 **HTTP 404 + Spring 风格 `{"status":404,"error":"Not Found"}`**，**没有 `code` 字段** ——
  探接口时判 `code === 404` 会把所有 404 误判成「端点存在」。
- 各接口 body 格式不统一：有的只认 **form-urlencoded**，有的只认 **JSON**（传错分别报「订单号不能为空」/ HTTP 415）。
- 订单号格式校验很严：`YYYYMMDDHHmmssSSS-` 后接**恰好 14 字符**。探接口请用**格式合法但不存在的**假单号，别拿真单试破坏性接口。
- 座位图与门店详情是 `await` 回来的，比页面渲染晚 —— 所以异步回调里都要补刷座位数、时段摘要、时长行。漏掉就会出现「明明有 24 个空位却显示空 0」这种假象。
- 时间字段格式不统一：订单详情返 `10:00`（短），订单历史返 `2026-10-17 10:00:00`（全）。直接 `slice(0,5)` 会把全格式截成 `2026-`。已改用正则提取 `HH:mm`。
- 订单开始时间**根本没有 `beginTime` 字段**：详情接口给的是 `date` + `begin`（`2026-10-20` + `10:00`）。读错字段得到 `NaN`，
  「取消扣减窗口」和「提前开门窗口」会双双失效 —— 表现就是**开门按钮永远可点**。统一走 `orderBeginAt()` / `orderEndAt()`。
- 门店清单接口**分页有 bug**：`pageSize=200` + `pageNo=2` 时平台会把**第 1 页原样再返回一遍**，
  按 `pageCount` 翻页永远只能凑到 200 家，后面 25 家（含南宁航洋国际店）被静默丢掉。
  改成 `pageSize=1000` 一次取全，再按 `storeId` 去重兜底。
- 自己写 in-flight 合并时，**必须先把 promise 塞进 map 再 await**。先 await 再 set 会让并发全部穿透，
  5 个请求全打上游 —— 这个 bug 写错过一次，表现为 `X-WZZ-Cache` 全是 `miss`。
